          設定
          
  
          
    
          
      
      
      
    
          
    
          
      
          
        
          外観
          
        
          
          
          
          
          DuoTone・Agila・Material・Kronuz・ayu（いずれもMIT）の配色から選びます。選ぶとすぐ反映します。
          
          
          
        
          
        
          
          
          サイドバー・下のパネル・AIパネルの開閉と幅・高さを初期値に戻します。
          
          
          
        
          
        
          
          
          
          ボードごとの「次回から表示しない」をすべて消します。
          
          
          
        
          
      
          
      
          
        
          AI
          
        
          
          
          
          OpenAI・Claude・Geminiから選びます。キーと設定は提供元ごとに別に保存します。
          
          
        
          
        
          
          
          
          キーはこのブラウザから提供元へ直接送り、弊社のサーバーへは送りません。
          
          
        
          
        
          
          
          
          候補から選びます。候補に無いものは「詳細設定」のモデルIDで指定します。
          
          
        
          
        
          詳細設定
          
          
            
            
          候補に無いモデルのIDをそのまま入力します。
          
            
          
          
          
          
            
            
          AIへの接続方式です。候補モデルを選ぶと自動設定されます。
          
            
            
          Responses：OpenAIの新しい接続方式。
          Chat Completions：OpenAIの従来の接続方式。
          Messages：Claudeの接続方式。
          Generate Content：Geminiの接続方式。
          モデルが対応する方式を使う必要があります。
          
          
          
        
          
        
        
          
        
          
          
          いま表示している提供元とモデルを次回の起動時に開く設定として保存します。キーは保存しません。
          
          
          
        
          
        
          
          
          この提供元のキーと保存設定をすぐ消します。閉じても戻りません。

          技適について
          
        
          
          
          「技適マークは、電波法令で定めている技術基準に適合している無線機であることを証明するマークで、個々の無線機に付けられています。」[1]
          
          
          同じ製品でも古いロットには表示が無いことがあります。手元の基板、シールド缶、パッケージのどれかで確認してください。
          
        
          
        
          
        
          表示が無い場合
          
        
          
          
          「技適未取得機器を用いた実験等の特例制度」の届出をすると、実験等の目的での使用ができます。[2]
          
        
          
        
          
          
          項目内容
          
          
            
          手続き届出制度で、事前の審査や許可はありません。届出が到達した時から効力を持ちます。
          
            
          目的科学または技術の発達のための実験、電波の利用の効率性に関する試験、電波の利用の需要に関する調査のいずれか。
          
            
          期間届出の日から 180 日以内（電波法第4条の2第3項、電波法施行規則第6条の3第2項）。
          
            
          対象規格告示で指定されています。Wi-Fi（IEEE802.11b/a/g/n/ac/ad/ah/ax/be）、Bluetooth Core Specification 2.1 以降、IEEE802.15.4 など。全部の列挙は令和元年総務省告示第263号にあります。[3]
          
            
          適合の確認機器が相当する技術基準に適合していることは、仕様書や外国の認証などで利用者自身が確認します。
          
            
          回数同じ目的・規格で届出できるのは 1 回限りです。
          
            
          届出先総務大臣。Web での届出は電波利用電子申請[4]から行います。開設届出の案内もあります。[5]
          
                    
        
          
        
          
          
          最新の条件は総務省のページで確認してください。この節は 2026-09-20 に確認した内容です。
          
          
          使うかどうかの判断は利用者が行います。この節は法的助言ではありません。

          ライブラリ
          
        
          
          
          左のアクティビティバーの「ライブラリ」で PlatformIO Registry を検索し、提供者・正式名とバージョンを選んで、そのプロジェクトの直接依存に加えます。
          
          
          追加先は今開いているプロジェクトです。view の上に、そのプロジェクト名と選択中のボード名が出ます。
          
          
          Git の URL や任意のパスを直接足す方法はありません。実際のパッケージを取りに行くのは Build のときです。
          
          
          名前を押すと、説明・Registry 番号・「バージョンを選択」／「削除」がその名前のすぐ下に開きます。追加済みは見出しを押すと開き、件数は「追加済み」の右隣の数字です。
          
        
          
        
          
          
          Registry に登録されていることや、framework / platform の表示は、そのボードとの互換性の保証ではありません。
          
          
          設定済みと、取得済みと、対象ボードでの Build 成功と、実機での動作確認は、それぞれ別のことです。
          
        
          
        
          
        
          このボードでは使えないライブラリ
          
        
          
          
          Build ハーネスで実際に失敗を見たものだけを表にしています。検索結果では既定で伏せられ、「このボードで使えないライブラリも表示」で出すと行に「使えません」が付き、理由と代替は詳細の中にあります。
          
        
          
        
          
      
          

      
          
        
          持ち出し
          
        
          
          
          名前を付けたプロジェクトのコード・ボード・直接依存は、同じブラウザの中に自動保存します。クラウド同期でもバックアップでもありません。
          
          
          エクスプローラ右上の「ファイル」メニューで、「ファイルへ書き出す」は編集中の 1 件を zip にし、「すべて書き出す」は保存してあるプロジェクトを全部まとめて 1 つの zip にします。
          
          
          「ファイルから読み込む…」で zip と旧 JSON を新しいプロジェクトとして増やせます。エクスプローラへ zip をドラッグ＆ドロップしても同じです。取り込んだ zip のボードがこの製品の対応ボードに無いときは、読み込むボードを選びます。
          
        
          
        
          
          
          zip に入るのは、プロジェクト名・ボード・直接依存・版数を書いた digicode.json と、src/main.cpp の 2 つだけです。この zip は DigiCode Text へ戻すためのものです。
          
          
          API キー・会話・Build ログ・成果物・表示設定は zip に含みません。
          
        
          
      
          

      
          
        
          AI
          
        
          
          
          右の AI パネルは、左のアクティビティバーの「AI」で開きます。使い方は右の AI に聞けます（API キーが必要）。
          
          
          提供元は OpenAI・Claude・Gemini から選びます。キーとモデルは設定の「AI」の節で決め、キーと設定は提供元ごとに別に保存します。
          
          
          AI は回答か、main.cpp 全体の変更候補を返します。「コード変更時」が「自動適用」なら全体を置き換え、「確認して適用」なら差分を見てから適用します。回答だけではコードは変わりません。適用は Undo 1 回で戻せます。
          
          
          入力欄は Enter で送信、Shift＋Enter で改行です。
          
          
          会話はこのページの中だけに残ります。保存はしないので、リロードすると消えます。「会話を消去」は、いま表示しているプロジェクトと提供元の会話だけを消します。
          
          
          設定の「保存して閉じる」はこのブラウザに保存し、「保存せず使う」は開いているページだけに反映します。閉じるだけなら編集は破棄されます。
          
        
          
        
          
        
          AI に送るもの
          
        
          
          
          送るのは、現在のコード・ボード・直接依存と版、そして指示と保持中の会話です。「Buildエラーを含めて送信」を選んだときだけ、一致する失敗ログも送ります。中身は「AIに送る内容を確認」でそのまま読めます。
          
          
          上限は、コードが 256 KiB、指示が 16,000 文字、履歴が最大 12 往復・32,000 文字です。履歴のソースは重複して送りません。
          
        
          
        
          
          
          API キーと会話は、このブラウザから提供元へ直接送ります。弊社のサーバーへは送りません。キーと設定の保存は暗号化保管ではありません。
          
          
          任意のコードや会話の中の秘密の値を自動で見つける機能はありません。
          
        
          
      
          

      
          
        
          compile サーバー
          
        
          
          
          Build は、この画面からコードを compile サーバーへ送り、できた成果物を受け取ります。何も指定しなければ、この画面を配っているのと同じサーバーです。
          
          
          別のサーバーを使うときは、設定の「compile サーバー」の節に URL を入れます。空にすると同じサーバーに戻ります。保存先はこのブラウザだけです。
          
          
          URL を入れると、そのサーバーの /health を呼びます。応答があれば「接続できました」、届かなければ理由を出します。応答したことは、そのサーバーが生きていることだけを示します。
          
          
          ボード一覧はページを読み込んだときに取ります。URL を変えたあとは読み込み直してください。起動時にボード一覧を取れなかったときは、この設定が開いた状態で始まります。
          
        
          
      
          

      
          
        
          困ったとき
          
        
          
          
          画面に出ることどうするか
          
          
            
          「Build通信に失敗しました。再実行できます」ローカルの Build サーバーが動いているか確かめて、もう一度「Build」を押す。
          
            
          ビルド結果に「○○ は △△ で使えません」と出るそのボードで Build が通らないライブラリ。詳細に出ている代替へ替える。「ライブラリ」の節を見る。
          
            
          「このブラウザに自動保存：保存できません」「再試行」を押す。直らないときは「ファイルへ書き出す」で zip に退避してから触る。
          
            
          シリアルのポートを選び直したい「シリアル」タブの「USBポートを解除」で許可を手放すと、次の接続で選び直せる。
          
            
          書き込みの後に macOS が「ディスクの不正な取り出し」と言う正常な動作。
          
            
          Wio Node を micro USB でつないでも書き込めないWio Node の micro USB は給電専用で UART が無い。Grove の USB シリアルを PORT0 に挿す。
          
            
          ESP32-DevKitC V4 と同じ形の別売りボードで書き込めない対応ボードとして数えているのは Espressif 純正の ESP32-DevKitC V4 だけ。同じ Build がそのまま使えることが多いが、自動リセットが効かない個体では Boot を押したまま EN を押してから書き込む。
          
                    
        
          
        
          
          
          ポートが出てこない、ドライバ、権限など、実機をつないで初めて分かることは、まだここに書けることがありません。
          
          
          実機確認待ち。
          
        
          
      
          

      
          
        
          このソフトについて
          
        
          
          
          DigiCode Text は、ブラウザで main.cpp を編集し、ローカルの compiler（Node と PlatformIO）でマイコン向けに build して、そのままブラウザからボードへ書き込む Web アプリです。
