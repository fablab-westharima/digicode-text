*Editor / LSP (S003a) — detail and type labels in `investigations/2026-08-26_editor-lsp-spike/`:*

- **Editor は donor 資産ゼロ**(Classic は Blockly のみ)。OSS 選定になる。
- **同一機能で実測**: Monaco **brotli 900 KiB / 起動 1,087 ms** vs CodeMirror 6 **145 KiB / 262 ms**(Monaco 側は `editor.worker` 未計上の**下限**)。**semantic 機能は両者同一** — 同じ clangd を見るため。
- 🔴 **Monaco の diagnostics は owner 名前空間で分離される**(Compiler 診断と LSP 診断が同一ファイル上で共存)。CodeMirror の `lint` は単一集合。
- 🔴 **browser-side clangd WASM の公開ビルドは wasm32-wasi sysroot 焼き込みで `Arduino.h` も ESP32 core も無い。** `clangd.wasm` 実配信 **24.5 MiB (gzip)**。**実装コストを支配するのは size でも隔離でもなくこの sysroot 問題。**
- 🔴 **COOP/COEP では親が非隔離だと iframe も隔離されない**(`allow="cross-origin-isolated"` を付けても不変)。**`Document-Isolation-Policy` なら親に広告を置いたまま iframe だけ隔離でき、親の third-party script/image も読み込まれた。** Google 公式は **GPT が COEP ページを未サポート**と明記。
- 🔴 **素の clangd は `.ino` を認識しない**(シンボル 0)。Arduino プリプロセッサがするのは **`#include <Arduino.h>` 挿入 / 全関数プロトタイプ生成 / `#line` 写像**の 3 つだけ → **`.ino` → `main.cpp` の機械変換は実装可能、逆は不要**。**`.ino` 経路では全スケッチファイルが build dir へコピーされる**ので URI 変換層は `.ino` 専用ではない。
- 🔴 **arduino-language-server 0.7.7**: `referencesProvider` / `implementationProvider` **未実装**、`hierarchicalDocumentSymbolSupport` 非宣言の client には **panic でプロセス終了**、初回診断 **18.2〜18.7 s**(`main.cpp` 経路の約 12 倍)。
- **`@codemirror/lsp-client` は CodeMirror 作者本人の一次公式パッケージ**(MIT)— S001 の「コミュニティ製」は古い。**`clangd-in-browser` は `private:true`/`v0.0.0` の実験デモ**で依存が 28 メジャー遅れ。

*Local Helper (S003b) — detail and type labels in `investigations/2026-08-26_local-helper-feasibility/`:*

- 🔴 **Extension 無し・Helper 1 個で成立。** HTTPS(public address space)から `ws://127.0.0.1` の LSP が開き、Monaco から multi-file semantic navigation が全部動いた。**代償は「HTTPS 配信」と「ブラウザ許可 1 回」の 2 点だけ。**
- 🔴 **未許可では Helper に 1 バイトも届かない**(negative control 済み)。**HTTP 配信では `local-network-access` が `denied` 固定**で回避不能。仕様は **WICG Local Network Access**、Chrome **142**(WebSocket **147**)、**Firefox も shipping**。🟢 **mixed content は障害ではない** — 遮断していたのは permission。

- 🔴 **Helper 無しで基本 Editor は壊れない** — 起動 **921 ms**、検索・編集・**compile 診断 → file/line jump** 動作、**エラーポップアップ 0**。Helper 死亡でも動き続け**古い赤線を掃除**、復活は**操作ゼロで 3.9 s**。5 フェーズ通して **JS 例外もダイアログも 0**。
- 🔴 **偽診断 0 件を達成**(esp-clangd + フラグ除去 + `-isystem` 6 行、**`--query-driver` 不要** = GCC **91.4 MiB** 同梱不要)。S003a の残課題の決着。
- **配布サイズ**: esp-clangd **10.5〜13.5 MiB**(**tar entry 3 つ、バイナリのみ。clang builtin ヘッダを含まない**)+ board 1 枚の LSP 用ヘッダ **64 MiB → xz 6.0 MiB**。対して **ESP32 core 一式は 5.3 GB**。

- 🔴 **donor DigiCode-Helper の資産**: axum ローカル HTTP API + Origin 許可リスト + CORS、**4 プラットフォームの GitHub Actions ビルド**、**Tauri updater + minisign + `latest.json`**、GitHub Releases ホスティング。🔴 **無いもの: macOS Developer ID / notarization / Windows Authenticode**(全文検索 0 件)。🔴 **`0.0.0.0` bind と認証なしは真似してはならない。**
- **Native Messaging**: `allowed_origins` にワイルドカード不可(installer が extension ID を知る必要)、**Chrome と Edge で ID もマニフェスト置き場も別**、**native host → Chrome は 1 MB 上限**。**挟む積極的理由は実測範囲で見つからなかった。**
