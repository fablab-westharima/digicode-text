# 07_コスト比較 — FS 講座 20〜50 人 / 100 人同時 / Local Helper との分離会計

**Acceptance 13 / 14 / 15 に対応。裁定 §12 / §13 / §14。**
**検証の型:** メモリ実測は **real-fire**。VPS 価格は **各社の公式ページ (primary source)**。
**特定 provider を採用決定しない**(裁定 §13)。

---

## 1. 🔴 前提数値の補正 — 前 spike の 261 MiB は楽観側だった

裁定 §13 は「前実測 clangd ≈261 MiB / session を基準にしつつ、必要なら最新 probe で補正」と定めた。
**補正が必要だった。**

前 spike の 261 MiB は **ESP8266 の 5 ファイル / 100 行**プロジェクトでの値である。
DigiCode Text の主対象である **ESP32** で測り直した:

| 条件 | 1 セッションあたり RSS |
|---|---|
| 前 spike: Apple clangd / **ESP8266** fixture | **261 MiB** |
| 本 spike: Apple clangd / **ESP32** fixture | **≈502 MiB** |
| 本 spike: **esp-clangd** / ESP32 fixture | **≈520 MiB** |

**変数を切り分けた結果、差を作っているのは clangd のビルドではなく board(ESP32 の IDF ヘッダ量)である。**
→ **現実的な基準値は 1 セッション ≈ 500 MiB。前 spike の値のほぼ 2 倍。**

### メモリは加算されるか(共有ページで得をしないか)

8 セッションまで 1 つずつ立ち上げて実測:

| 同時セッション | 合計 RSS | 1 あたり |
|---|---|---|
| 1 | 525.7 MiB | 525.7 |
| 2 | 1,062.8 | 531.4 |
| 4 | 2,079.3 | 519.8 |
| 6 | 3,128.3 | 521.4 |
| **8** | **4,176.4 MiB** | **522.1** |
| 8(15 秒アイドル後) | 4,164.1 MiB | 520.5 / **CPU 合計 0.0 %** |

**1 → 8 の比 = 7.94。つまりほぼ完全に線形で、共有ページの恩恵は無い。**
🔴 **アイドル時 CPU は 0.0 %。律速はメモリであって CPU ではない**(前 spike の結論を 8 並列でも再確認)。

## 2. 100 人同時利用の server-side 所要メモリ

| 方式 | 必要 RAM(clangd 分のみ、500 MiB/session 基準) |
|---|---|
| **naive 100 process** | **≈50 GB** |
| idle timeout(無操作 10 分で停止) | **同時に「セッションを保持している」人数で決まる。** 講座中は全員がアクティブなので **削減効果はほぼ無い** |
| on-demand 起動(操作時だけ起動) | 同上。**編集中の講座では常時起動と大差ない** |
| process pool(N 個を使い回す) | **プール数 × 500 MiB**。ただし clangd はワークスペース単位で index を持つため、**別プロジェクトを同じプロセスで扱うと index が混ざる**(本 spike の probe でも scratch 内の同名ヘッダを拾う現象を観測)。**分離のためのワークスペース切替コストは未測定** = `NOT OBTAINED` |

🔴 **裁定 §13 が挙げた最適化は、どれも「利用がまばらな一般公開」には効くが、
「講座で全員が同時に編集する」場面には効かない。** これが本節の核心である。

## 3. FS 講座 20〜50 人 — 4 案の比較(裁定 §12)

| 軸 | **A. Server-side LSP** | **B. Local Helper** | **C. 教室に LSP サーバ 1 台** | **D. LSP なし** |
|---|---|---|---|---|
| **講師の準備** | 🟢 ほぼ不要(サーバは常設) | 🔴 **事前に Helper を配る段取り**(MDM / USB / 事前案内) | 🔴 **当日 1 台をセットアップ**し、URL/IP を配る | 🟢 不要 |
| **受講者の準備** | 🟢 **ブラウザだけ** | 🔴 **1 回のインストール + 許可**(`06` §1: 署名済みなら macOS クリック3+許可1) | 🟢 ブラウザだけ | 🟢 ブラウザだけ |
| **当日トラブル** | 🟡 サーバ側の障害は**全員に同時に効く** | 🟡 **個別に起きる**(Gatekeeper・ポート・PC 性能)。ただし**壊れても基本 Editor は動く**(`04` 実測) | 🔴 **1 台落ちたら全員止まる** + 教室 LAN 依存 | 🟢 ほぼ無い |
| **corporate restriction** | 🟢 影響小 | 🔴 **インストール禁止 PC では成立しない** | 🟡 教室 LAN のポリシー次第 | 🟢 影響なし |
| **internet** | 🔴 必須・帯域も要る | 🟢 **編集中はローカル完結**(compile はクラウド) | 🟡 教室 LAN のみで可 | 🔴 compile に必要 |
| **受講者 PC の RAM** | 🟢 不要 | 🔴 **+500 MiB 程度**。8 GB の PC なら現実的、4 GB は厳しい | 🟢 不要 | 🟢 不要 |
| **server cost** | 🔴 **20 人 ¥15,400 / 50 人 ¥30,800 の桁**(§2) | 🟢 **ゼロ** | 🟡 **教室 PC 1 台**(既存機材なら実質ゼロ、ただし 50 人なら 25 GB RAM が要る) | 🟢 ゼロ |
| **setup 時間** | 🟢 0 分 | 🔴 **受講者 1 人 2〜5 分 × 人数**(署名なしなら Gatekeeper/SmartScreen で延びる) | 🟡 講師 15〜30 分 | 🟢 0 分 |
| **rollback** | 🟢 サーバを戻すだけ | 🟡 各 PC で旧版へ(Tauri updater 経由) | 🟢 1 台戻すだけ | — |
| **実測で成立を確認したか** | ✅ 前 spike | ✅ **本 spike で全経路** | ⚪ **未実測**(A の構成をそのまま LAN に置くだけなので成立自体は自明) | ✅ 本 spike phase1 |

🔴 **C(教室サーバ)は本 spike の実測に照らすと過小評価されがちな案である。**
50 人 = 25 GB。**教室に 32 GB の PC が 1 台あれば足りる**し、
受講者は**ブラウザだけ**で済む。**運営の月額もゼロ**。
代償は「当日その 1 台を立ち上げる講師の手間」と「1 台落ちたら全員止まる」こと。
**ただし C は本 spike では実測していない。**

## 4. コストの分離会計(裁定 §14)

「サーバ代ゼロ = コストゼロ」ではない。4 つに分けて比べる。

### ① monetary infrastructure cost(実際に払う金)

| | Server-side LSP | Local Helper |
|---|---|---|
| 常時 | 🔴 **利用者数に比例**。100 人同時で ¥61,600 / $504 の桁 | 🟢 **ゼロ**(配布は GitHub Releases、donor 実績あり) |
| 増加の形 | **線形**(メモリが加算的であることを実測) | **一定** |

### ② engineering maintenance cost(人の時間)

| | Server-side LSP | Local Helper |
|---|---|---|
| ビルド対象 | 1 つ(サーバ) | 🔴 **macOS Intel / macOS ARM / Windows(/Linux)の 4 系統** — donor の workflow が既にある |
| 署名 | 不要 | 🔴 **Apple Developer ID + notarization、Windows Authenticode。donor には無い**(`03` §6)。鍵管理も乗る |
| 更新 | サーバを更新すれば全員に反映 | 🔴 **利用者の手元に配る**。Tauri updater が donor にあるので機構は流用可 |
| **board headers / clangd の更新** | 🟡 サーバ 1 箇所 | 🔴 **利用者数分に配る**(H4 なら pack 単位で済む — `05` §3) |
| security fixes | 🟡 サーバ 1 箇所で直せる | 🔴 **配り直すまで古い版が動き続ける**。ただし自動更新があれば緩和 |
| 濫用対策 | 🔴 **rate limit / quota / cleanup / セッション上限が必須**(匿名無料のため) | 🟢 **不要**(計算資源が利用者のもの) |
| **偽診断の品質** | 🟡 サーバに board toolchain を置けば同等 | 🟢 **同等**(`05` §1 で 0 件を実測) |

### ③ support cost(問い合わせ)

| | Server-side LSP | Local Helper |
|---|---|---|
| 発生源 | 🟡 障害時に**集中して**発生 | 🔴 **導入時に個別に発生** — Gatekeeper / SmartScreen / ブラウザ許可 / ポート / 会社 PC の制限 |
| 質 | 「今日使えません」 | 「インストールできません」「有効になりません」 |
| 緩和 | — | **署名で許可 2 手分が消える**(`06` §1)。**Helper 無しでも基本機能は動く**ので、支援が間に合わなくても講座は進む(`04` phase1 実測) |

### ④ UX cost(利用者が払うもの)

| | Server-side LSP | Local Helper |
|---|---|---|
| 開くまで | 🟢 **0 手**。ブラウザだけ | 🔴 **クリック 3 + 許可 1**(署名済み macOS)/ **クリック 5〜6 + 許可 4**(未署名 Windows) |
| 高度解析の即時性 | 🟢 最初から | 🔴 導入した人だけ |
| **入れない人の体験** | — | 🟢 **基本 Editor + AI + compile + 診断ジャンプは全部動く**(実測) |
| PC 資源 | 🟢 消費しない | 🔴 **≈500 MiB + 起動時の CPU** |
| プライバシー | 🟡 **コードがサーバへ出る** | 🟢 **出ない**(compile 時を除く) |
| オフライン | 🔴 不可 | 🟢 編集と解析は可能 |

## 5. 🔴 この節が Human に渡す一行

**Server-side LSP のコストは「利用者数 × ≈500 MiB」で線形に増え、
その最適化(idle timeout / on-demand / pool)は、講座のように全員が同時に編集する場面では効かない。**
**Local Helper はその金額をゼロにするが、engineering・support・UX の 3 つのコストへ振り替える。
そのうち support と UX の大部分は「署名」という一回の投資で削れる。**

**そして本 spike の実測が示した第三の事実:**
**どちらを選んでも、選ばなかった人の体験は壊れない** —
Helper 無しでも基本 Editor・AI・compile・診断ジャンプは動く(`04` phase1)。
**つまりこれは「どちらか一方」ではなく「既定をどちらに置くか」の決定である。**
