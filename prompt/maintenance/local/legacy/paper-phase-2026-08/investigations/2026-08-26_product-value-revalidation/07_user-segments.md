# 07_利用者別の有効性 — 誰に有効で、誰には不要か

**Human 指示 §17 に対応。「全ユーザーに優れる」という結論は求められていない。**

**凡例:** ◎ 明確に有効 / ○ 有効 / △ 限界的 / ✕ 不要(既存環境のほうが良い)

---

## 1. 一覧

| 利用者 | Web 版 | Desktop 版 | 判定の理由 |
|---|---|---|---|
| **熟練 MCU 開発者** | ✕ | ✕ | VS Code + PlatformIO + debugger + Git + 任意 toolchain が全面的に優る。**保証された狭い環境は制約でしかない**。DigiCode Text が獲得を狙うべき層ではない |
| **AI Agent を使える開発者** | ✕ | ✕ | Claude Code / Copilot / Cline 等がローカル環境で multi-file を扱える。**DigiCode Text の AI がこれに勝つ見込みは無い**(`08` §7) |
| **Arduino 経験者(自由な個人 PC)** | △ | △ | 既に環境が動いている。**移行動機は「別 PC でもすぐ使える」程度**。ライブラリ地獄に嫌気が差している層には ○ になりうるが、**それは既存環境の不満であって本製品の価値ではない** |
| **初学者(自由な個人 PC)** | ○ | △ | 環境構築の崖を消す価値は本物。ただし **Arduino Cloud Editor / Codey / Wokwi と正面から競合**(`02` §4-3 / §5-1)。**差は保証と日本語と教材連携**であり、細い |
| **学校(PC 教室・共有端末)** | ◎ | ○ | 🔴 **最有効セグメントの一つ。** 共有端末に環境を作れない・作っても消える・全員に同じ状態を配れない(Arduino IDE 2.x は portable mode が無い / A-2)。**Web 版なら端末側に何も残さない** |
| **FS 講座等の研修** | ◎ | ○ | 🔴 **当日 0 分で全員が同じ環境**。inherited real-fire: Helper 無しで Monaco 起動 921 ms・診断ジャンプ動作。**server-side LSP を必須にしない裁定により、受講者数に比例する費用が発生しない** |
| **企業イントラ PC** | ◎ | ◎ | 🔴 **最有効セグメント。** 許可すべき宛先が**ベンダ 1 ドメイン**に畳める(`03` §9)。ただし 🔴 **AI provider への到達が別途要る**(§2 の警告) |
| **管理者権限のない PC** | ◎ | ✕ | 🔴 **ここが Web 版が主製品である決定的根拠。** Desktop も既存 IDE bundle も Arduino Cloud Agent も**インストール権限を要求する**。Web 版だけが成立する |
| **一時利用・ワークショップ** | ◎ | ✕ | 貸出 PC / 会場 PC に痕跡を残さず終われる。**書き込みまでブラウザで完結する**(Arduino Cloud は Agent 必須 / A-6) |
| *(追加)* **iPad / Chromebook 中心の教室** | △ | ✕ | 🔴 **Safari には Web Serial も Web Bluetooth も無い**(inherited)= 書き込み経路が 1 本も無い。「編集のみ可」という第 3 の状態が要る(baton 13)。ChromeOS は対応とされるが **実挙動は `NOT OBTAINED`** |
| *(追加)* **AI 利用が制限された教育現場** | ○ | ○ | AI = 主機能という裁定と衝突する。**AI 無しでも「環境が要らない」価値は残る**が、製品の主機能を切った状態になる。**未検討の論点**(`08` §9) |

## 2. 🔴 セグメント判定に効く 2 つの横断的事実

### 2-1. 「権限」が最も強い分岐線

インストール権限の有無だけで、成立する選択肢が次のように切り替わる:

```
権限あり + 通信自由     → 既存環境が最強。DigiCode Text は不要
権限あり + 通信制限あり → Desktop 版 / offline bundle が候補。DigiCode Text Desktop は有力
権限なし + 通信制限あり → 🔴 DigiCode Text Web 以外に選択肢がほぼ無い
権限なし + 通信自由     → Arduino Cloud(Agent 必須で書き込み不可)/ Codey / DigiCode Text Web
```

🔴 **3 行目が DigiCode Text の中核市場である。** そしてそれは
**学校・企業イントラ・一時利用 PC** と正確に重なる。

### 2-2. 🔴 AI 主機能と企業セグメントの衝突

企業イントラで package manager が遮断される環境は、
**LLM API エンドポイントも遮断されうる**(inferred。実測は `NOT OBTAINED`)。

| 影響 | 内容 |
|---|---|
| 最有効セグメント(企業イントラ)で **主機能が動かない可能性** | 🔴 |
| 緩和手段は donor に既にある | 🟢 provider 抽象に `custom` endpoint があり、Local LLM のヘルプページも存在(`donor-audit/03`) |
| **設計として明示的に扱われていない** | 🔴 baton にも裁定にも無い。`08` §8 risk / §9 unknown に登録 |

## 3. 誰に不要かを明言する(Human 指示 §17 の要求)

🔴 **次の層に対して DigiCode Text を売り込むべきではない:**

1. **熟練 MCU 開発者** — 保証された狭い環境は制約にしかならない。debugger も Git も無い。
2. **AI Agent を使いこなす開発者** — ローカルの AI Agent のほうが強い。
3. **自由な個人 PC で既に環境が動いている Arduino 経験者** — 移行の動機が無い。

**この 3 層を対象から外すことは、rule 17 の意味での「自己スコープ縮小」ではない。**
Human 指示 §17 が「誰には不要かを明確にせよ」と明示的に要求しており、
**これはその要求への回答である**(スコープ決定そのものは Human のもの)。

## 4. この節の一行

🔴 **DigiCode Text の価値は「利用者の PC に対する権限と通信の自由度」に反比例する。
自由な PC を持つ人ほど不要になり、制約された PC しか使えない人ほど代替が無くなる。**
