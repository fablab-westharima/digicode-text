description: Session close protocol — baseline measurement → case-filing check → full 16.md rewrite → 改定log append → index reconciliation → commit+push (no confirmation) → close report → separate follow-up report (template feedback / observations)
---
Close the session. Execute the steps below in order, all of them, no omissions (the close-side counterpart of the rule 13 cold start):

**Top principle (2026-07-20 user directive — S012 lesson)**: once told to close, **closing silently is the top priority**. **Interactive confirmation during close is forbidden** (do not question the user mid-procedure). **commit+push are included in the close instruction and run without confirmation** (conditional on passing the pre-commit gate; stop and report only if gitleaks or similar flags). Template feedback, observations, proposals and anything not part of close itself go into a **separate report after** the close report (registered as a blanket-GO exception to rule 12 wait-for-go).

0. **Pre-entry reconcile (before anything else — 2026-08-17 directive)**: list (a) every authority-relevant delta since the last user GO — a gate turned red, a new case filed, a change outside the enumerated scope, an approved acceptance condition missed — and (b) every unresolved user-response / user-decision dependency. Empty list → proceed silently into step 1. One or more entries → present the list in one message and **wait for a fresh close GO** (this is the one sanctioned pre-close question; the no-interactive-confirmation principle applies from step 1 onward). Minor technical deltas (comment wording, formatting) do not fire this. (Origin: S005 — a close order issued at 11:08 was executed at 11:42 across a budget red that materialized in between.)

**State claims require their artifact (applies to every step below — 2026-08-17 directive)**: any state claim written into the close report, 16.md, or a session file — "pushed", "clean", "green", "complete", "0 remaining" — must be backed by its verification command run in this session ("pushed" → `git log origin/HEAD..HEAD` empty; "clean" → `git status --porcelain` empty), output observed, not recalled. A claim without its command is written as [未verify]. (Origin: S005 reported "push 完了 (clean)" while the receiver commit had never been pushed to origin.)

1. **Baseline measurement**: measure HEAD commit / typecheck / lint / test counts / bug-index totals / rules and case counts. Transcribing previous values is forbidden. Report any divergence in the close report. **Sessions that delegated also record the route / mode / lane mix** — plus the session's `PRIMARY_MODEL_MODE` (declared or default `T1-solo` — rule 22 §Session mode) and its `SESSION_ROLE` (declared or default `PRIMARY` — rule 22 §Session role); per delegation: route (A/B/C/D), `AUTHORITY_MODE`, and lane, counted per the 6 lanes (rule 22 §Success criteria question 1 can only be answered this way and cannot be reconstructed later; an `IMPLEMENTATION`-only month is exactly the decay this rule exists to catch, and an all-`DELEGATED`, never-`HUMAN_DIRECT` record answers whether Route C is real). Also note any requested≠observed model event and any mode-boundary violation (a `HUMAN_DIRECT` report that asserted acceptance/completeness/mergeability instead of observed results — judged by the report's shape per rule 22 §Roles, not by a banned-word list) — both are §Success criteria findings. Route/mode/lane records are diagnostic context, never targets: state the eligible-task denominator alongside the mix, and a period with zero delegation or zero Route C is normal when no eligible task arose. If nothing was delegated, one line: "no delegation". **Also run `bash scripts/usage-report.sh`** — it emits the AI USAGE REPORT table (per-actor model, turns/calls, tokens: parent / subagents / Codex threads, with its coverage limits printed in its own footer). The table goes into the close report (step 9) as emitted — its unit and coverage lines are part of the instrument's output, never restated from memory (rule 04 §A gauge reports its unit). A NOT OBTAINED from the script is reported as NOT OBTAINED, never as zero. **Also look at untracked items** — for each `??` line of `git status --porcelain`, resolve it as one of **commit / add to `.gitignore` / delete** (the decision is one of the three; "leave it" is not an option). rule 04 §instrument-dimension 3 mandates "if the harness seeds fixtures, delete them and confirm zero residue via `git status`", but that section's trigger is "when accepting a change to something rendered" and **never reaches the close moment** — this is that edge. Measured 2026-08-16: on a consumer project, an untracked directory created during acceptance-harness work survived close with zero mention in the close commit, handover or session file, and no `.gitignore` entry.

2. **This session's incident check (no deferral)**: ask whether this session had judgment mistakes, rework, user corrections, or rule violations. If yes, append the case to `prompt/maintenance/global/rules/common/judgment-mistakes-history.md` Part 2 **now, in this session**, and add a row to the Part 1 case index (deferred cases are never written — measured discipline). If structural, promote to a rule and add a decision-tree row. **After appending a case, retroactively apply its lesson to your own recent claims, pass verdicts and staged deliverables** (adversarial retroactive self-application — the case-filing protocol in judgment Part 1). Findings are fixed or registered before close. **Re-measure every §5 row whose input the tree has moved since step 1 ran — the trigger is "the tree changed after step 1", whoever or whatever changed it** (this step, a later step, a hook, a subagent, an editor, you by hand). The narrower form of this clause said "if *this step* changed files", and it measurably did not fire: the S004 close recorded case index 60 while its own commit's tree measured 61. A number you cannot name the measuring moment of is not a baseline, even when it was honestly measured.

3. **Full current-state OWNER SET rewrite, in ONE commit**: **overwrite** `prompt/maintenance/local/handover/16_次セッション引き継ぎ指示書.md` (never create a new numbered file — 16.md is a proper noun) **and update every other declared owner in the same commit** — `local/handover/batons.md` (baton bodies) and `local/handover/evidence-map.md` (evidence / provenance / loop position / template-feedback queue). The owner set and which of them are unconditional are owned by `CLAUDE.md` §0; `local/README.md` §OPTIONAL CAPABILITY owns the three obligations this step discharges. **Same commit is not a tidiness preference**: a partially updated owner set is the split's characteristic failure — each file stays internally consistent, so nothing looks wrong, and the fact that fell between them is silent. **`GEN:` advances in every owner, not only the router** (selftest **B70** compares them and is red if one lags). **Every baton keeps its one-line stub in §2 while its body lives in `batons.md`** — the stub is what makes the body a safe conditional read (measured 2026-08-27 over the 45 batons then present: 31 were safe conditionally *only* because of the stub), so deleting a stub is deleting a protection, not a duplicate. Selftest **B71** checks the correspondence both ways. §3 settled entries are 5-tuples (decision, rejected option, rejection ground, date, and the prior ruling it supersedes — or `none`) / §5 holds step 1's measured values. **Size: `local/README.md` §handover owns that convention and it is not a line limit** — do not restate a number here, and never delete current truth to reach one (the non-removable list is in that section). **Set the `GEN:` line to this close (`S{NNN}-close`)** — the hook injects a frozen copy of this file at every session start, so a session holding both that copy and a mid-session re-read cannot otherwise tell which is current; a GEN left at the previous close is a silent claim that nothing changed. **The router DECLARES the generation; every other owner CARRIES it.** 16.md is the only file that may originate a GEN value (selftest B52 checks that value against the newest `sessions/` file, so step 3 and step 5 must agree); `batons.md` and `evidence-map.md` copy the router's line verbatim in the same commit, and selftest B70 is red if any of them lags. Before S008 this sentence read "GEN lives only in 16.md", which contradicted the same paragraph's "advance it in every owner" — an actor taking the second half would have made B70 red, and one taking the first half would have violated the first half of this very step.

   **After rewriting, run `bash scripts/handover-diff.sh` (mandatory).** It scans the whole owner set and compares their UNION, printing per-owner denominators; a row that moved from the router to the body owner is therefore not a loss, while a body deleted under a surviving stub still is. It lists items that left §2/§3, split into REWORDED and GONE. **Classify every GONE item in the close report before committing** — **done (name the commit) / relocated (name the file that owns it now) / dropped by the user (name the ruling) / lost (put it back)**. REWORDED is detected mechanically and needs no answer. "Silently gone" is not an option, and **a close does not proceed while any item is still classified LOST** — restore it first. Report the denominator the tool printed (files scanned, entries before/after) alongside the classification: a run that parsed nothing prints almost the same sentence as a clean sweep, which is why it now exits non-zero instead. Record the classification as ✅ rows in §2 or in the close report.

   > Why mandatory: 16.md is overwritten at every close, so **a requirement can leave the project without appearing in any diff anyone reads**. Measured (LaserEditor S021 investigation, 2026-08-16): a requirement the user supplied verbatim became a §2 row asking "include it? (**default: no**)", vanished with its work row at the next close, and **git records no user decision for the exclusion** — while the very commit that dropped the row recorded the opposite ruling. At no instant in the 3 steps does a line exist saying "scope was cut". Read rule 17 §Handover mechanics alongside (**turning a requirement into a default-exclude question is itself a rule 17 violation**).

4. **CLAUDE.md consistency (mandatory, immediately after step 3)**: walk `CLAUDE.md` against the handover you just wrote and fix any contradiction **in this same commit**. Check specifically that **§2 and §3 assert no current fact at all** — no session number, no plan or phase name, no revision, no completed point, no next task, no blocker, no GO-waiting item, no baton content, no measured count. They are pointer-only *by construction*, so anything concrete there is a defect, not an update. Also check §4's strategic axis is filled (never placeholders), §7's structure table still matches the tree, and §9's absolute rules do not contradict a ruling recorded in §3 of the handover.

   > Why it is its own step: `CLAUDE.md` is injected into every session before anyone decides anything, and it has no update trigger of its own — so a fact copied there outlives its owner and keeps reading as current. Measured in this repository: a `case index 45` line survived three closes at an actual of 48, and the discipline note that replaced the number still left a headed slot for the current task. Guarded by selftest **B54**; the guard exists because this kind of step has been deleted from a close procedure before, in a consumer project, and went unnoticed for four closes.

5. **Session file + index append**: create `prompt/maintenance/local/handover/sessions/S{NNN}_{YYYY-MM-DD}_{slug}.md` (format = `global/templates/session-log-template.md`: §0 purpose re-examination / §1 work done / §2 state changes — state "no new rules/cases" explicitly when true / §3 self-assessment ✅Healthy・⚠️Warning). **A ⚠️Warning is never left as prose — convert each one, before closing, into one of**: (a) a 16.md §2 task row (with owner and a consuming trigger) / (b) a case filing / (c) "acknowledged, not acting" + explicit reason. Session files are immutable, so a Warning written only there enters nobody's work plan. Measured: on a consumer project, "the parent cannot see the screen" sat in §3 twice for 3 sessions; the trigger for action was the user's screenshot (case 87 = 6 layout breaks in an implementation that passed all static acceptance). Same file: a `created_at` omission stayed Warning-only for 2 straight sessions. rule 12 imposes a registration duty for **the user's** unease but imposed none for **your own observations**. Also append one line to the index at the end of `改定log.md`. Rewriting past session files or index lines is forbidden (1 session = 1 immutable file; never write content directly into 改定log.md).

6. **Index reconciliation**: if bugs / plans changed state, make physical file locations (active⇄closed etc.) and each index.md agree. maintenance_index.md only on structural change.

7. **Record template-feedback candidates (no questions during close)**: if this session changed `global/rules/common/` (new rule / new case / rule revision / hook improvements), record "should this feed back to Project_Template (`fablab-westharima/Project_Template`) as project-independent?" as a **candidate for the step 10 separate report** (do not ask the user during close). Actual feedback happens after the user's Yes, with an origin note (`origin: <project> Session N`), per the template's OPERATIONS.md §2. If nothing qualifies, leave one line in the close report saying so.

8. **commit + push (no confirmation)**: check for uncommitted changes and, as blanket GO included in the close instruction, **commit + push without asking the user**. Condition = the pre-commit gate's gitleaks scan passes (run trufflehog manually before going public). **Stop and report only when the scan flags**, then await the user's decision. **A gate and the push never share a command batch**: any gate run at close (selftest, tests) has its RC taken in an independent run on its own line (`RC=$?`, no pipe, no `&&`-chain into commit), the 0 is observed, and only then do commit/push run as separate commands. (Origin: LaserEditor S025 case 110 — `selftest | tail; echo RC=$?` fused into the commit+push batch let tail's 0 shadow a true RC=1 and a red gate reached origin; case 82's pipe lesson re-fired at the close boundary.) In a `SESSION_ROLE: REVIEWER` session the commit carries only the review report, the 16.md baton row, and close artifacts — repo-body files stay untouched (rule 22 §Session role).

   **The evidence is the FINAL tree, not an earlier green.** Every §5 number and every gate result quoted in the close must hold for the tree that actually enters the commit — a green taken before the last edit is evidence about a tree nobody kept. Re-run the gate and the baseline once the working tree is final, and take the RC on its own line. **Then run the gate again after the commit and the push**: checks whose input is commit-granular (a generator reviewed "at or after" the newest feeder commit, anything reading `git log`) cannot fire before the commit exists, so a pre-commit green is not evidence about them. Report both runs.

9. **Close report (≤5 lines + the usage table)**: output "done this session / next session's starting point / remaining 🔴" concisely, followed by the AI USAGE REPORT table from step 1 pasted as emitted. The next session auto-receives the updated 16.md **in full** via the SessionStart hook, plus the manifest — paths only — of the conditional owners; their bodies are reached on their triggers and are deliberately not injected.

10. **Separate report (after the close report)**: template-feedback candidate confirmation (1 question), session observations, proposals, and anything else not part of close itself. Omit if empty.
